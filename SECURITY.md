# Security Policy

## Supported versions

MLXServe is developed on `main`; fixes land there. There are no maintained release branches.

## Reporting a vulnerability

**Do not open a public issue for security problems.**

Report them privately through GitHub: <https://github.com/ROSITO/SoloMLX-server/security/advisories/new>
(repository **Security** tab → **Report a vulnerability**). Only the maintainer sees the report.

Please include:

- what an attacker can do, and from where (local process, LAN, internet when exposed behind a proxy);
- steps to reproduce, with the `MLXSERVE_*` settings involved (`MLXSERVE_HOST`, `MLXSERVE_API_KEY`, JWT, CORS);
- the commit you tested.

You can expect a first answer within a week. Once a fix is merged, the advisory is published with credit to you,
unless you prefer to stay anonymous.

## Scope

In scope: the HTTP API and web UI (authentication, rate limiting, input handling), anything that lets a request
read or write files, run commands, or exhaust the host's memory despite the memory guardian.

Out of scope: content generated by models (wrong or harmful answers), and a server reachable from other machines
(`MLXSERVE_HOST=0.0.0.0`) without `MLXSERVE_API_KEY`: the API is then open by design to whoever can reach it.
Set a key when exposing it (see [docs/REVERSE_PROXY.md](docs/REVERSE_PROXY.md)).
